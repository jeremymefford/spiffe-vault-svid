# SPIFFE + SPIRE + Vault SVID Lab (Kubernetes + Nomad)

This lab demonstrates a mixed deployment model where trust is shared via SPIFFE IDs and x509-SVIDs across two trust domains with federation:

- `modern-app` (Go, in Kubernetes, trust domain `modern.lab`): gets its own x509-SVID from the SPIRE Workload API.
- `vault` (in Nomad, trust domain `legacy.lab`): issues a constrained URI SAN certificate for the legacy identity.
- `legacy-app` (Spring Boot, in Nomad): logs into Vault via AppRole, mints its x509-SVID-style cert, and calls the modern app over mTLS.

No secret values are hardcoded in code or manifests. All secret seed values are generated by the primer script.

## Architecture

1. `scripts/primer.sh` generates secret seed values in `.lab/lab-secrets.env`.
2. A modern trust domain root CA is generated locally (`infra/pki/modern-root-ca.*`).
3. Nomad dev agent runs locally, and a Vault dev job is deployed on `http://127.0.0.1:18200`.
4. Vault generates the legacy trust domain root CA internally, exports the public cert to `infra/pki/legacy-root-ca.crt`, and is configured to issue one allowed URI SAN:
   - `spiffe://legacy.lab/ns/legacy/sa/springboot`
5. SPIRE server (Kubernetes) uses the modern trust domain CA as its upstream authority (`disk` plugin).
6. SPIRE server registers a federated bundle for `legacy.lab` so workloads in `modern.lab` trust the legacy root.
7. SPIRE agent runs in-cluster and serves Workload API on `/run/spire/sockets/agent.sock`.
8. `modern-app` runs in Kubernetes and requires client SPIFFE ID exactly:
   - `spiffe://legacy.lab/ns/legacy/sa/springboot`
9. `legacy-app` runs as a Nomad batch job, mints its cert from Vault, and calls:
   - `https://localhost:30443/hello`

The legacy root private key never leaves Vault. The federated bundle and legacy client cert chain are built from the Vault-issued CA.

## Data Flow

1. Legacy app logs into Vault with AppRole and requests a cert with URI SAN `spiffe://legacy.lab/ns/legacy/sa/springboot`.
2. Legacy app builds a client TLS context from that cert chain, and trusts the modern root CA.
3. Modern app gets its x509-SVID from SPIRE Workload API in `modern.lab`.
4. Modern app validates the legacy client via the federated `legacy.lab` bundle.

- `kind`

## Quickstart

```bash
./scripts/lab.sh up
./scripts/lab.sh verify
./scripts/lab.sh verify-negative
./scripts/lab.sh down
```

## Primer (Generate Secrets)

```bash
./scripts/primer.sh
```

This creates `.lab/lab-secrets.env` and CA material if missing.

To rotate generated secret seeds:

```bash
./scripts/primer.sh --rotate
```

## Bring Up The Lab

```bash
./scripts/lab.sh up
```

What this does:

- Runs `scripts/primer.sh`
- Starts Nomad dev agent locally (if not already running)
- Deploys Vault as a Nomad job
- Creates kind cluster `spiffe-vault-lab` (if missing)
- Deploys SPIRE server + agent in Kubernetes
- Registers modern app SPIFFE ID in SPIRE (`unix:uid:1000` selector)
- Registers the `legacy.lab` federated bundle in SPIRE
- Builds and loads modern app image into kind
- Deploys modern app service on `https://localhost:30443`
- Configures Vault PKI (legacy trust domain) + AppRole and writes `legacy-app/lab.env`

All of the underlying scripts still work directly if you prefer (for example `./scripts/lab-up.sh`).

## Run Legacy App (Nomad)

```bash
./scripts/lab.sh legacy
```

This builds `legacy-app` into a Docker image, submits a Nomad batch job, then prints allocation logs.

Expected output includes:

- minted legacy SPIFFE ID
- HTTP 200 from modern app
- modern app response showing accepted client SPIFFE ID

## Verify Federation

```bash
./scripts/lab.sh verify
```

This confirms:
- Vault is the legacy trust domain CA.
- SPIRE has the federated bundle for `legacy.lab`.
- Modern app accepts the legacy SPIFFE ID over mTLS.
- Modern app logs the legacy client identity and its mTLS certificate.

To prove enforcement, run the negative test (temporarily removes the bundle and expects failure):

```bash
./scripts/lab.sh verify-negative
```

## Useful Validation Commands

```bash

```

Show SPIRE registration entries:

```bash
kubectl exec -n spire statefulset/spire-server -- /opt/spire/bin/spire-server entry show
```

## Tear Down

```bash
./scripts/lab.sh down
```

This stops Nomad jobs/agent and deletes the kind cluster.

## Notes

- This is a teaching lab, not production hardening.
- Separate roots per trust domain keep the federation boundary explicit; production setups should use stronger key isolation and rotation workflows.
- Vault runs in `-dev` mode for simplicity.
